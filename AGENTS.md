### What this is

**Decifra** turns a corpus into categorical variables using a researcher-defined codebook and an LLM. It fills the output table automatically and keeps **validation against human coding** as a first-class step. It is not a manual QDA tool. The researcher still designs the codebook, chooses corpus/model/parameters, interprets results, and decides through validation whether the coding is research data.

- **Current state**: [`docs/MVP_STATUS.md`](docs/MVP_STATUS.md) (verified) and [`docs/ROADMAP.md`](docs/ROADMAP.md) (task briefs). A functional **single-variable** MVP runs today. R1.1, multi-variable and multi-label codebooks, was signed off on 2026-09-13 (spec §15). Steps 1, 2 and 4 are merged. **Step 3 is pending**: extraction, estimates and storage do not consume `Codebook.variables` yet.
- **Original product brief** (problem, MVP scope, architecture decisions, codebook format, data model, screens, validation rationale, build order, V7 pilot data): [`docs/PRODUCT_BRIEF.md`](docs/PRODUCT_BRIEF.md). Its architecture decisions still hold. Where it and a later spec or `ROADMAP.md` differ, the later document wins.
- **First external use case**: `bbsia-radar` ([#4](https://github.com/mancano-tales/decifra-text-as-data/issues/4)). The radar produces the corpus and Decifra classifies it. What the radar needs is built **here**, in general form, never as a radar-specific hack.
- Names: the product and repo are `decifra`; the Python package is `text_as_data` (renaming it is deferred); the CLI is `decifra`.

### Rules

- **Spec first** for anything non-trivial. Write a design spec in `docs/superpowers/specs/`, then a plan in `docs/superpowers/plans/`, then code. `ROADMAP.md` says which briefs need a spec. Do not add a feature outside your brief; append it to `TODO.md` Pending instead.
- **Validation is not optional.** Any change to `codebook.py`, `extraction.py` or `validation.py` keeps `pytest` green, and new behavior gets tests. A codebook for a real domain is validated against a human-coded sample before its output counts as data.
- **Codebook and engine stay separate.** Codebooks change often; the engine should not. Editing `extraction.py` for one specific codebook signals that the abstraction needs rethinking, not a one-off fix.
- **Architecture is closed** (brief § Architecture):
  - local Python backend (FastAPI + SQLite), "sidecar-ready": it must answer `curl` with no frontend open;
  - no cloud or third-party server;
  - a provider layer with API-key mode (schema enforced by `instructor`) and CLI mode (best effort);
  - structured output derived from the codebook, with `rationale` and a verbatim `evidence_span`.
- **UI strings go through i18n**; never hardcode English in a screen. Backend error `detail` stays English.
- **`TODO.md`**: append pending items; move finished ones to Done with a date. When a non-trivial slice ends, write a short **learnings** note (in the Done entry, or in `docs/` if large): what was assumed, what turned out wrong or harder, and what to check next time.

### Commands

- Install: `python -m venv .venv`, then `python -m pip install -e ".[dev]"` and `npm --prefix frontend ci`
- Tests: `PYTHONPATH=src pytest`; frontend: `npm --prefix frontend run lint` and `npm --prefix frontend run build`
- Run the MVP: `npm --prefix frontend run build`, `python scripts/build_frontend.py`, `decifra serve` (http://127.0.0.1:8765; `--data-dir PATH`)
- Dev with live reload: `scripts/dev.sh` or `powershell -File scripts/dev.ps1` (backend :8000, Vite :5173)

### Current pitfalls

- **Several sessions at once: use `git worktree`, never the same directory.** Read [`docs/MULTI_AGENT_WORKTREES.md`](docs/MULTI_AGENT_WORKTREES.md) before anything that switches branches or discards working-tree state. The 2026-09-02 incident is in `docs/research/2026-09-02_git_safety_governance_for_shared_agent_working_directory.md`. The `PreToolUse` hook (`.claude/settings.json` → `tools/guard_git_command.py`) is defense in depth, not a substitute.
- **Editable installs follow the environment, not the worktree.** Use one `.venv` per worktree, or `PYTHONPATH=src pytest`.
- **Windows CLI mode**: resolve the CLI with `shutil.which()` (npm `.cmd` shims) and decode subprocess output with `encoding="utf-8"`, never `text=True`. Both bugs are fixed in `providers.py`; do not regress them.
- **The main local folder is still named `cifra-text-as-data`** on the author's machine, on purpose: renaming it would break the linked worktrees.
